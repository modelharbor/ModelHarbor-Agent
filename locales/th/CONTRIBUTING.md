# การมีส่วนร่วมใน ModelHarbor Agent

## ก่อนที่คุณจะมีส่วนร่วม

### 1. หลักปฏิบัติ

ผู้มีส่วนร่วมทุกคนต้องปฏิบัติตาม[หลักปฏิบัติ](./CODE_OF_CONDUCT.md)ของเรา

### 2. แผนงานโครงการ

แผนงานของเราเป็นแนวทางในการดำเนินโครงการ จัดแนวการมีส่วนร่วมของคุณให้สอดคล้องกับเป้าหมายหลักเหล่านี้:

### ความเชื่อถือเป็นอันดับแรก

- ตรวจสอบให้แน่ใจว่าการแก้ไข diff และการรันคำสั่งมีความเชื่อถือได้อย่างสม่ำเสมอ
- ลดจุดความยุ่งยากที่ทำให้ผู้ใช้ไม่อยากใช้งานประจำ
- รับประกันการทำงานที่ราบรื่นในทุกภาษาและแพลตฟอร์ม
- ขยายการสนับสนุนที่แข็งแกร่งสำหรับผู้ให้บริการ AI และโมเดลที่หลากหลาย

### ปรับปรุงประสบการณ์ผู้ใช้

- ปรับปรุง UI/UX ให้ชัดเจนและใช้งานง่าย
- ปรับปรุงขั้นตอนการทำงานอย่างต่อเนื่องเพื่อตอบสนองความคาดหวังสูงที่นักพัฒนามีต่อเครื่องมือใช้งานประจำ

### เป็นผู้นำในด้านประสิทธิภาพ Agent

- สร้างเกณฑ์การประเมินที่ครอบคลุม (evals) เพื่อวัดผลผลิตในโลกแห่งความเป็นจริง
- ทำให้ทุกคนสามารถรันและตีความ evals เหล่านี้ได้ง่าย
- ส่งมอบการปรับปรุงที่แสดงให้เห็นการเพิ่มขึ้นของคะแนน eval อย่างชัดเจน

กล่าวถึงการสอดคล้องกับพื้นที่เหล่านี้ใน PRs ของคุณ

## การค้นหาและวางแผนการมีส่วนร่วมของคุณ

### ประเภทของการมีส่วนร่วม

- **การแก้ไขจุดบกพร่อง:** แก้ไขปัญหาในโค้ด
- **ฟีเจอร์ใหม่:** เพิ่มฟังก์ชันการทำงาน
- **เอกสาร:** ปรับปรุงคู่มือและความชัดเจน

### แนวทาง Issue-First

การมีส่วนร่วมทั้งหมดต้องเริ่มต้นด้วย GitHub Issue

- **ตรวจสอบ issues ที่มีอยู่**: ค้นหา [GitHub Issues](https://github.com/modelharbor/ModelHarbor-Agent/issues)
- **สร้าง issue**: ใช้เทมเพลตที่เหมาะสม:
    - **จุดบกพร่อง:** เทมเพลต "Bug Report"
    - **ฟีเจอร์:** เทมเพลต "Detailed Feature Proposal" ต้องได้รับการอนุมัติก่อนเริ่มต้น
- **อ้าง issues**: แสดงความคิดเห็นและรอการมอบหมายอย่างเป็นทางการ

**PRs ที่ไม่มี issues ที่อนุมัติแล้วอาจถูกปิด**

### การตัดสินใจว่าจะทำงานอะไร

- ตรวจสอบ [GitHub Project](https://github.com/orgs/RooCodeInc/projects/1) สำหรับ "Good First Issues" ที่ยังไม่ได้มอบหมาย
- สำหรับเอกสาร เยี่ยมชม [ModelHarbor Agent Docs](https://github.com/modelharbor/ModelHarbor-Agent-Docs)

### การรายงานจุดบกพร่อง

- ตรวจสอบรายงานที่มีอยู่ก่อน
- สร้างจุดบกพร่องใหม่โดยใช้ [เทมเพลต "Bug Report"](https://github.com/modelharbor/ModelHarbor-Agent/issues/new/choose)
- **ปัญหาความปลอดภัย**: รายงานเป็นการส่วนตัวผ่าน [security advisories](https://github.com/modelharbor/ModelHarbor-Agent/security/advisories/new)

## กระบวนการพัฒนาและส่งงาน

### การตั้งค่าการพัฒนา

1. **Fork & Clone:**

```
git clone https://github.com/YOUR_USERNAME/ModelHarbor-Agent.git
```

2. **ติดตั้ง Dependencies:**

```
pnpm install
```

3. **Debugging:** เปิดด้วย VS Code (`F5`)

### แนวทางการเขียนโค้ด

- หนึ่ง PR ต่อหนึ่งฟีเจอร์หรือการแก้ไข
- ปฏิบัติตามแนวทางปฏิบัติที่ดีของ ESLint และ TypeScript
- เขียนคอมมิตที่ชัดเจนและบรรยายได้โดยอ้างอิง issues (เช่น `Fixes #123`)
- ให้การทดสอบที่ครอบคลุม (`npm test`)
- Rebase ลงบน branch `main` ล่าสุดก่อนส่ง

### การส่ง Pull Request

- เริ่มเป็น **Draft PR** หากต้องการความเห็นในช่วงแรก
- อธิบายการเปลี่ยนแปลงของคุณอย่างชัดเจนตาม Pull Request Template
- ให้ภาพหน้าจอ/วิดีโอสำหรับการเปลี่ยนแปลง UI
- ระบุหากจำเป็นต้องอัปเดตเอกสาร

### นโยบาย Pull Request

- ต้องอ้างอิง issues ที่ได้รับการอนุมัติและมอบหมายล่วงหน้า
- PRs ที่ไม่ปฏิบัติตามนโยบายอาจถูกปิด
- PRs ควรผ่านการทดสอบ CI สอดคล้องกับแผนงาน และมีเอกสารที่ชัดเจน

### กระบวนการตรวจสอบ

- **การคัดกรองรายวัน:** การตรวจสอบอย่างรวดเร็วโดยผู้ดูแล
- **การตรวจสอบเชิงลึกรายสัปดาห์:** การประเมินที่ครอบคลุม
- **ปรับปรุงอย่างรวดเร็ว** ตามความเห็น
